# REQ-320..326 - Unblock P3a: pointwise scoring, pillar review, spot-check agreement, freeze

Status: G2 contracts ready

## Requirements

### REQ-320 - Pointwise judge scoring pipeline

A tool scores archived baseline packages (and any tracked story package) with
the configured judge set from `eval/judges.json` plus the supplemental local
Codex judge. Each artifact is sampled `samples_per_artifact` times per judge,
aggregated by median, and recorded as `eval-score-record/v1` rows plus a
per-judge result file. Inputs are fingerprinted (artifact + rubric + judges +
manifest); a changed input invalidates saved results and forces re-measurement.
Saved complete results are reused on re-run. Pointwise prompts share no context
with pairwise probes. This produces the "30 scored cases" evidence P3a is
blocked on (10 archived baselines x 3 judges).

### REQ-321 - Dimension correlation matrix and pillar grouping review

A tool computes the 10x10 Spearman correlation matrix over per-case dimension
medians from pointwise score records, applies the manifest's
`pillar_grouping_review.merge_threshold`, and emits a review report with merge
recommendations and an inter-judge view. The report is the
`pillar_grouping_review` input the manifest has been waiting on; it may still
conclude "no change".

### REQ-322 - Internal spot-check agreement

A tool joins blind human scores (desktop evaluation root,
`rater_type=internal_spot_check`) with judge score records on artifact content
hash and computes `spot_check_agreement` (nominal Krippendorff alpha on binned
scores plus per-dimension judge-human mean differences). When data exists, the
evaluator metrics report stops marking this metric
`not_computable_here`.

### REQ-323 - Governance page is generated, never hand-maintained

`docs/eval-governance.html` is regenerated by a tool that injects every number
from the eval manifest and derives the current-status section from repository
state (case counts per split, adversarial pair count, story-eval test count).
A `--check` mode wired into governance CI fails when the tracked page drifts
from what the tool would produce.

### REQ-324 - Freeze enforcement

A freeze record (`eval/manifests/FREEZE.json`) pins the sha256 of the manifest
and rubric together with evidence links (scoring run, pillar review, spot-check
report). Once a record exists, `scripts/check_eval_freeze.py` fails on any
drift, so changing the frozen set requires the documented MAJOR bump. The
freeze is written only after the human evidence exists; building the mechanism
first is what makes the freeze one command later.

### REQ-325 - Stage-1 seven-path masking probe (authoring)

Six new targeted degradations of the shared comedy_002 baseline cover the six
remaining masking recipes from `STORY_EVAL_ADVERSARIAL.md` §2 (HOOK_FAKE, false
callback, EMOTION_UNEARNED, VOICE_COLLAPSE, PLOT_CONVENIENCE, TROPE_STACK); the
seventh path (MOTIVE_EXPLICIT) already exists as the stage-0 narrow pair. Every
negative passes all admission gates, keeps episodes/scenes/length confounds
controlled, and carries a load-bearing defect (`repair_cost: scene_rewrite`).
Defect keys live in `pair.json`, never in the artifact. Measurement runs
through the existing probe tool; the scale-up decision (15-40 pairs) follows
the §9 branch rule and is out of scope here.

### REQ-326 - Case set expansion to 120 before freeze

The pilot grows from 30 to 120 cases at the parent contract's genre quotas
(family 20; urban_romance, revenge, suspense 16 each; workplace, rural, comedy
12 each; historical, cross_genre 8 each) and its 30:30:24:12 split ratio with
premise families never separated across splits. `holdout` stays sealed at 0
(no valid consumer in v1). Split assignment, quota validation, the manifest
splits block and the eval README all move together, before any freeze, so one
freeze covers the target scale.

## Acceptance

- pointwise scoring of the archived baselines completes with resume and
  fingerprint invalidation covered by tests that mock the transport;
- the pillar review tool reproduces a merge recommendation on fixtures with
  known correlated dimensions;
- spot-check agreement is computable from a fixture desktop evaluation root;
- `generate_governance_page.py --check` fails on a hand-edited page and passes
  after regeneration;
- `check_eval_freeze.py` passes without a freeze record, and fails on drift
  once one exists;
- every stage-1 negative passes admission gates and differs from the baseline
  only by the declared edits;
- `validate_cases.py` and `split_cases.py --check` pass at 120 cases.

## Exclusions

- generating baselines for the 90 new cases (separate cost decision);
- the 15-40 pair adversarial scale-up (follows the stage-1 probe reading);
- professional panel engagement, skill derivation and promotion (P7/P12);
- `proxy_fidelity` (blocked on the first retained production candidate set);
- freezing anything before the blind human evidence exists.
